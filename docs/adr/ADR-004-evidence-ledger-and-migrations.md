# ADR-004 — Append-only evidence ledger and numbered migrations
**Proposed 2026-10-23 (Sprint 1; needs owner acceptance).** (1) Evidence confidence is derived from origin in code and constrained by a CHECK; rows are immutable except `last_confirmed_at`, enforced by SQLite triggers. Human input can never produce `OBSERVED` or `VERIFIED`. (2) Schema changes are numbered Python/SQL migrations, each in its own transaction with foreign keys off, preceded by an online-backup file and followed by `foreign_key_check`; the application refuses to run on a stale or newer schema. (3) Scans never read file contents, never follow symlinks and exclude credential-like names; Git is invoked with `core.fsmonitor=false` and `--no-optional-locks`. (4) A bare-date deadline means 23:59:59 Europe/Istanbul, stored as UTC. (5) `projects.path` was removed in favour of `project_sources`; the Sprint-0 `path` key remains in API output as the primary source. **Consequence:** `events` is still not trigger-protected; consider the same for Sprint 2.

**Amendment 2026-10-23 (schema v3, Sprint 1 acceptance):** `events` is now trigger-protected; `evidence.seq` gives a gap-free recording order independent of rowids and timestamps; nested/duplicate source paths are refused by trigger; timestamps carry microseconds; write transactions use `BEGIN IMMEDIATE`. These protections are against ordinary application code, not against a privileged local user (not cryptographic). **Recommended disposition: Accept as amended** — owner sign-off pending (`plans/SPRINT_1_ACCEPTANCE.md` §6).
